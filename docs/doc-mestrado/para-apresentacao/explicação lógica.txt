---
  1. Evento - Login, logout ou falha

  Quando um usuário tenta fazer login no sistema, o AuthenticationService processa a autenticação e, independente do resultado (sucesso ou falha), o BlockchainService é chamado para registrar esse evento. Os
  dados capturados são:

  - ID e email do usuário
  - Tipo do evento (LOGIN_SUCCESS, LOGIN_FAILED, LOGOUT)
  - Score de risco calculado pela IA (Isolation Forest + Random Forest + Deep Learning)
  - Decisão tomada (PERMITIDO, NEGADO, REQUER_MFA)
  - Endereço IP de origem
  - Geolocalização
  - Fingerprint do dispositivo
  - Timestamp

  ---
  2. Hash SHA-256 - Dados do evento são hasheados

  O sistema pega todos esses dados, concatena em uma string e aplica o algoritmo SHA-256, que gera um hash único de 64 caracteres hexadecimais. Por exemplo:

  Dados: "usuario=1|evento=LOGIN_SUCCESS|risco=0.23|ip=192.168.1.1|timestamp=2026-03-13T14:00:00"
          ↓ SHA-256
  Hash: "a3f2b8c91d4e7f6a0b5c8d2e1f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1"

  A propriedade do SHA-256 é: se qualquer caractere dos dados originais for alterado, o hash resultante é completamente diferente. Isso é o que permite detectar adulterações.

  ---
  3. Bloco - Transação adicionada ao bloco

  O sistema cria um objeto TransacaoBlockchain que é persistido no banco de dados com:

  - O hash calculado (hashTransacao)
  - O hash dos dados originais (hashDados)
  - Todos os dados do evento
  - Status de confirmação (PENDENTE → CONFIRMADO)
  - Número do bloco
  - Hash do bloco

  Esse registro é a transação - é o que você vê na tabela quando seleciona um usuário na tela de Blockchain.

  ---
  4. Encadeamento - Hash do bloco anterior garante imutabilidade

  Cada novo bloco contém o hash do bloco anterior. Isso cria uma cadeia:

  Bloco 1                    Bloco 2                    Bloco 3
  ┌──────────────┐          ┌──────────────┐          ┌──────────────┐
  │ Hash: abc123 │◄─────────│ Hash ant: abc123│◄───────│ Hash ant: def456│
  │ Dados: ...   │          │ Hash: def456 │          │ Hash: ghi789 │
  │ Transações   │          │ Dados: ...   │          │ Dados: ...   │
  └──────────────┘          └──────────────┘          └──────────────┘

  Se alguém alterar os dados do Bloco 1, o hash dele muda. Mas o Bloco 2 ainda referencia o hash antigo do Bloco 1 → a verificação falha → adulteração detectada.

  É exatamente isso que o botão "Verificar Integridade" na tela faz: recalcula o hash e compara com o armazenado.

  ---
  Resumo para a banca: O sistema usa blockchain como trilha de auditoria imutável. Cada evento de autenticação é hasheado com SHA-256 e encadeado ao bloco anterior, garantindo que qualquer tentativa de alterar
   registros históricos é imediatamente detectável.
